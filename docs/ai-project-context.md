更新日：2026-11-14。これはCV教材ライブラリを使うコードの作成・修正をAIに依頼するとき、最初に渡すための文書です。**APIやデータ列をこの文書へ重複転記せず、下記の正本を必ず確認してください。** 実装と文書を照合せずに、動作するコードや無欠陥を保証するものではありません。

## 1. プロジェクトの目的

高校生が身近な課題を画像で扱う試作品を作るためのPythonライブラリです。課題や用途を一つに決めつけず、データの内容・権利・形式を理解したうえで、生徒が入力や出力を選べるコードを作ってください。

- PyPI配布名：`cv-data-lesson`
- Python import名：`cvlesson`
- 公開安定版：`0.1.0`
- 通常導入：`python -m pip install cv-data-lesson`
- 実行環境の標準：Google ColabまたはPython 3.11〜3.13のローカル環境
- 基本機能：データカタログとデータ取得
- モデル機能：分類・回帰、OCR、物体検出、領域分割、SDXL画像生成/Image-to-Image。機能ごとに依存導入と実行環境が異なる。

### Colabのinstallセルを作るとき

現行の公開安定版は`0.1.0`です。`0.1.0a1`〜`0.1.0a9`は過去のalpha版なので、新しいNotebookのinstall行に使わないでください。版を固定する必要がなければ、PyPIの安定版を選ぶ次の形を使います。

```python
%pip -q install cv-data-lesson
```

データ一覧・取得・DataFrame・基本画像表示だけならこれで足ります。Pillowは基本依存に含まれています。モデルを実際に使うNotebookでは、その機能のextraだけを付けます（分類・回帰は`[torch]`、OCRは`[ocr]`、検出・領域分割は`[vision]`、SDXLは`[diffusion]`）。同じNotebookで複数機能を使う場合は必要なextraを一つのinstall行にまとめます。再現性のため版固定が必要な場合は、alpha版ではなく安定版`==0.1.0`を指定します。

`ipywidgets`はNotebookのコードが実際にwidgetを使う場合に限り追加します。`nbformat`は既存Notebookを実行するための依存ではなく、PythonからNotebookファイルを生成・編集する開発ツールです。`Pillow`は基本依存なので、通常は別途installしません。コード中にimport文があるというだけでなく、実際に使う機能と`pyproject.toml`の依存を照合してinstall行を作ってください。Colabでは`!pip`ではなく`%pip`を使います。

## 3. 実装上の必須ルール

- 実在するID、引数、戻り値、表の列だけを使う。分からないときは先に`datasets.list_available()`、`datasets.info(id)`、取得後の`frame.columns`を確認する診断コードを作る。
- カタログ参照/importだけではデータを取得しない。明示的な`datasets.get(id)`の後に固定Releaseのartifactがダウンロードされ、既定ではリポジトリ外キャッシュへ保存される。
- データ全体のZIP取得とDataFrame作成を区別する。`to_df()`の画像列は原則ファイルパスで、画像バイト列を表へ読み込まない。列はデータごとに異なる。
- 画像APIの基本入力はファイルパスまたはPillow Image。NumPy画像配列を直接渡さない。実際の機能別APIはリファレンスに従う。
- GPUを暗黙に選ばない。対象機能の`available_devices()`で環境を確認し、必要なら`device`を明示する。CPUで実行できる例を基本にし、Colab GPUが必要なら前提を明記する。
- `ResNetClassifier`/`ResNetRegressor`はscikit-learnに似た`fit`、`predict`、`score`を使う。教師データと評価データを分ける。出力層が学習対象で、ResNet本体を全層微調整する機能ではない。
- OCR・検出・SAMは基盤モデルの推論。各データの教師注釈を使ったモデル追加学習や自動評価があると仮定しない。
- OCRResult等の構造化結果を保つ。表示画像を作る場合も元の結果を破壊せず、他処理へ渡す機械可読データの利用方法を示す。
- SDXL/LoRAの利用は数GB規模のモデル取得やGPUメモリを必要とすることがある。ユーザーの指定なしに全LoRAを順番にロードしない。ライセンスと取得元は対象LoRAの説明を確認する。
- データやモデルを公開・再配布したり、画像を外部送信したり、Git/PyPIへバイナリを追加しない。個人情報・第三者権利・データ固有ライセンスを考慮する。
- インストールが必要な場合、Colabは新規ランタイムを基本に、機能別extraを案内する。無関係なパッケージを削除したり、環境を一括更新したりしない。

## 6. 作成したコードの確認項目

- install名とimport名、Python版、機能別依存が現在の案内と合っている。
- データIDが`audience="student"`の正式一覧にあり、目的に合う。列名・単位・ラベル意味は取得後に確かめた。
- 学習・検証・テストの役割を守り、評価用データを学習に混ぜていない。
- 関数の引数、戻り値型、座標・画像寸法、配列shapeがリファレンスと合う。
- 表示を実行しただけでなく、戻り値・画像・数値が想定した形式であることを簡単なassert等で確認した。
- 実行していない環境や未取得モデルの動作を確認済みと書いていない。
- データの利用条件、AIの誤判定、人による確認が必要な箇所を示している。
