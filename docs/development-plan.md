# Phase 0〜2の開発計画

## 現在の状態

- Phase 0：リポジトリ構成、Codex向けの`AGENTS.md`、日本語README、固定Release取得機能の最小実装とオフラインテスト。
- 外部データ50候補の権利・実ファイル監査は未完了。登録だけで使用可能にはしない。
- `CV_sample_data`は完全に読み取り専用。変更は実施しない。

## Phase 1：取得・監査の整備

固定ReleaseへのHTTPアクセスを実機で検証する。ZIP全体のSHA-256、サイズ、ZIPの安全性、manifestとCSV・JSONLの整合性を確認。コネクタがReleaseへアクセスできることを確認する。ネットワークテストは通常のCIから分離。

## Phase 2：分類用Level 1の共通形式

トマトの葉などから訓練・検証・テストを安全に利用する方法を実装。元のテスト集合は変更しない。既存データの元リポジトリやReleaseを移動・更新しない。`festival_icons`はLoRA学習素材として別の形式で扱う。

## 教材との同期

Notebook v3は構造を維持。必要なコードセルだけ更新し、記入欄や説明を長くしない。発展LevelはNotebookに載せない。実装済みAPIだけ載せる。

## 公開条件

PyPIへ公開する前に、製品名の重複確認、READMEの実行例検査、リリース・バージョン固定、CIテスト、権利・ライセンス監査が必要。利用者承認なしに本番公開しない。

## Phase 1：手動での固定Release実体検査

固定タグのダウンロード、SHA-256検証、ラベル整合、全画像の読み込みを `cvlesson.audit` で確認します。通常の自動テストと切り離した手動ワークフローで実施し、検査結果はJSONに保存します。権利審査は別に行います。
